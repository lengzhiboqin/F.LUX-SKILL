# 每日巡检技能组（AI运营后台）

> 本技能是一段**无人值守**的固定流水线。除写表和发群消息外，不做任何额外动作。严格按顺序执行，每步没有对象就静默跳过（不写数据），最后统一播报。

## 0. 固定资源（禁止改动）

- 看板 docid：`s3_AGkA73j8ACICNB0RJwxoZTLWK96hH_a`（名称：AI运营后台项目管理看板）
- 子表（一律用 sheet_title 定位，不要用 ID）：
  - `①需求｜需求总表`
  - `②开发｜开发任务总表`
  - `③测试｜测试总表`
  - `④验收｜需求验收总表`
  - `⑤AI｜提示词库`（其中「需求拆解」是任务卡的标准，拆任务前先读它）
- 项目群：发消息前必须先跑 `wecom-cli message aibot sessions list`，按群名**唯一匹配**取本次的 `chat_id`，禁止复用历史 ID。
- 调用：wecom-cli 用 bytes 捕获 stdout 再以 utf-8(replace) 解码；结构/写记录用 `--json`，记录查询用 `--docid` + `--sql`。

## 0.1 执行前自检（必做）

1. 先 `wecom-cli identity whoami` 确认企业微信登录态有效。
   - 若未登录/登录态失效：**停止**，只给王先森单聊发一条「⚠️ 今日巡检未执行：企业微信登录态丢失，请重新登录后我再补跑」，不要反复重试，不要用其他途径绕过。
2. 用 `get_current_time`（Asia/Shanghai）锚定今天日期与星期。仅周一至周六执行；若周日被触发，直接静默结束（不播报、不写表）。
3. 会议时间窗口：`(今天-2天) 00:00:00` 到 `今天 23:59:59`，用 meeting_id 去重，覆盖昨天到今天所有会议。

## 0.2 通用铁律

- **只处理与「AI运营后台」项目开发相关的内容**（前端小程序、品牌后台、订单/商品/用户/数据等具体功能、问题、改进）。闲聊、与开发无关的业务、纯务虚展望不入表。
- **不编造**：需求与任务内容必须来自纪要原文或测试反馈原文；信息不足就不写，并在播报里说明。
- **不手改公式列**：需求状态、开发进度、测试结论、测试入口、测试状态、任务阶段、需求产生时间、上线状态、逾期状态均为原生公式，只读；只改基础字段，靠原生关联/公式流转。
- **ID 顺延**：写单选项前先 `fields list` 取该字段真实选项 id（用 `[{"id","text"}]`）；新增编号先查现有最大号顺延，`REQ-`、`BUG-`、`TASK-` 各自独立计数。
- 双向关联写入值为 `[{"record_id": "<被关联记录id>"}]`；写到开发表「关联需求」后，需求表「关联任务」自动回填。

## 第 1 步：会议 / 面聊智能纪要 → 需求池（人工待验证）

1. `meeting list` 拉时间窗口内会议（翻页直到 has_more=false），再 `meeting get`（每批≤10）取 `notes[].note_content`；只用 `has_note_permission=true` 且有文字纪要的会议。面聊若以独立记录存在，取其文字智能纪要；纯录音不处理。
2. 对每场会，以 `meeting_id` 为唯一键，先查需求表「来源记录」是否已含该 meeting_id（SQL 对 `来源记录` LIKE）；已处理则跳过该场。
3. 从纪要中**只提炼与项目开发相关、且具体到功能**的探讨点。每场会提炼 0~N 条：
   - 剔除：纯寒暄、与本项目无关的业务讨论、无法落地的宏大展望（如"以后要做 AI"）。
   - 保留：明确的功能点、流程问题、改进建议、要做的页面/规则。
4. 每条写入需求表：
   - `需求ID`：REQ-顺延；`需求名称`：一句话功能点；`需求类型`=需求；`需求来源`=会议纪要提炼；`验证状态`=**待验证**。
   - `功能要求（大白话）`：该探讨点具体要什么（来自纪要原文，大白话）。
   - `来源记录`：`会议主题(YYYY-MM-DD) meeting_id`（去重键，务必写）。
   - `优先级`：明显紧急给 P0/P1，否则一律 P2，交王先森验真伪时定。
   - `呈现形式`、`验收标准` 留空。
5. 记录：扫描会议场数、新增条数（用于播报）。

## 第 2 步：测试驳回 → 回写 BUG（静默跳过无驳回）

1. 查测试表：`负责人1结论="不通过" 或 负责人2结论="不通过"`，且 `已回写BUG=false` 的测试单。
2. 每条驳回单 → 在需求表写一条 BUG：
   - `需求ID`：BUG-顺延；`需求类型`=BUG；`需求来源`=测试反馈；`验证状态`=**真需求**（双人测试驳回即确认，直接进待拆解）；`优先级` 默认 P0（AI 可据现象降 P1）。
   - `需求名称`：`[BUG] 测试场景-问题一句话`。
   - `功能要求（大白话）`：问题现象 + 复现步骤（合并负责人1/2 的问题反馈原文）。
   - `关联测试`：`[{"record_id": 该测试单id}]`。
   - `来源记录`：`测试任务ID(YYYY-MM-DD)`。
3. 写完把该测试单 `已回写BUG` 勾选为 true（防重复）。
4. 没有驳回单则本步静默。

## 第 3 步：待拆解真需求 / BUG → 自动拆业务任务卡（全自动写入）

1. 查需求表：`验证状态="真需求" 且 关联任务为空`（即待拆解，含 BUG 池里已确认的 BUG）。
2. 排序：BUG 优先 → P0 → P1 → P2 → 最早产出。**每次只拆最优先的 1 条**，其余留到后续巡检。
3. 拆任务前先读 `⑤AI｜提示词库` 里「需求拆解」提示词，并遵守下列标准：
   - 一条需求最多拆 **3~5** 个任务，每个任务 **≤3 人天**；小功能/单个 BUG 直接 1 条；拆不出就不硬拆，把已明确的需求直接做成 1 条任务。
   - 每个任务只产出三样东西，**不写文件、接口、技术栈**（技术栈由编码 AI 自己读项目）：
     - `任务名称`：一句话，业务语言。
     - `复制给AI`：一段话，阿飞可整段复制给编码 AI——要做什么 + 操作路径（从哪个页面点进来）+ 业务规则/边界/异常 + 成功失败的中文提示。BUG 必须含「先说明报错根因，再修复；修完告诉我根因和改了哪里」。
     - `验收标准`：3~6 条编号的业务结果（点哪里、看到什么算对），不写技术术语。
4. 每个任务写入开发表：
   - `任务ID`=TASK-顺延；`任务名称`；`任务类型`（BUG→BUG修复、新功能→新功能、部署→配置部署）。
   - `优先级`：继承需求，BUG=P0；影响下单/收款/数据=P0，重要功能=P1，优化=P2。
   - `负责人`=阿飞；`开发状态`=待开发；`预估周期(人天)`。
   - `复制给AI`、`验收标准`；`关联需求`=`[{"record_id": 该需求id}]`。
   - `开始时间`、`截止日期`、`测试链接`、`代码链接` 一律留空。
5. 写入后需求表「关联任务」自动回填，需求状态由公式自动从「待拆解」变「待开发」，不要手动改。
6. 无待拆解则本步静默。

## 第 4 步：开发逾期检查 + 验收上线检查

**4a 开发逾期**：查开发表 `逾期状态="已逾期"` 的任务（公式已按"开发中 + WORKDAY(开始时间, 预估周期) < 今天"自动判定）。列出任务 ID、名称、负责人；逾期每天重复播报属于催办，不做去重。

**4b 验收**（查 `④验收｜需求验收总表`）：
- 待上线：`是否已合并main=false 且 待上线已提醒=false` → 播报"XX 已测试通过，待阿飞合并 main 上线"，随后把这些记录 `待上线已提醒` 勾 true。
- 已上线：`是否已合并main=true 且 已上线已播报=false` → 播报"XX 已合并 main、正式上线"，随后把这些记录 `已上线已播报` 勾 true。

## 第 5 步：项目群播报（固定模板）

先 `message aibot sessions list` 取项目群 chat_id，再以 markdown 发一条，格式固定、逐行换行：

```
📋 AI运营后台 · 每日巡检（MM-DD 周X 09:05）

√ 会议纪要：扫描 N 场，新增待验证需求 X 条
√ 测试BUG：无驳回
√ 需求拆解：无待拆解
√ 开发进度：无逾期
√ 验收上线：无变化

👉 今日第一件事：王先森到「需求池」验证 X 条新需求真伪
```

规则：
- √=该步正常/无新增/已自动处理；×=有需要人处理的事项。对应行有事项时把 √ 换成 × 并带数量、名称（如 `× 开发进度：TASK-001 修复订单删除报错 已超期 1 天，请阿飞处理`）。
- 最后「今日第一件事」仅在确有待办时出现，只给**当下最该做的一个动作**（谁、到哪个视图、做什么）；全员无事可做时省略此行。
- 全程大白话、不堆术语；称呼具体角色（王先森 / 阿飞 / 阿枫）。发完即结束。

## 异常处理

- 任一步查询/写入失败：在播报对应行用 × 注明"该项读取失败，请人工检查"，继续执行后续步骤，不中断整条流水线。
- 登录态失效按 0.1 处理。
- 遇到本 SOP 未覆盖的歧义（如字段缺失、选项对不上）：不要猜，写入播报末尾"⚠️ 有 N 处需王先森确认"，并列出问题。
