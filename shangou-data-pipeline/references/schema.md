## 8 张报表配置

页面：`https://shangoue.meituan.com/#/page/manageAnalysis/pc#/report`，表单全部在 `name="hashframe"` 的 iframe 内。
daily 模式**不操作任何日期控件**，直接用平台预填值。

| 报表名（=文件名前缀/总表名） | 分类 tab | radio value | 表单 | daily 数据日期 | 导出模式 |
| --- | --- | --- | --- | --- | --- |
| 门店财务明细 | 交易数据 | poiFinanceDetail | gen1 | 昨日(T-1) | task |
| 门店成交明细 | 交易数据 | poiDataDetail | gen1 | 昨日(T-1) | direct |
| 商品数据 | 订单数据 | product | gen1 | 昨日(T-1) | task |
| 问题订单数据 | 订单数据 | order | gen1 | 昨日(T-1) | direct（事件型） |
| 流量明细(新) | 流量数据 | trafficDetail | gen2 | 昨日·分天·分门店 | task |
| 流量渠道明细(新) | 流量数据 | trafficChannelDetail | gen2 | 昨日·分天·分门店 | task |
| 评价数据 | 服务数据 | evaluate | gen1 | **前日(T-2)** | direct（事件型） |
| 售后订单数据 | 服务数据 | afterSalesOrderDetails | gen1 | 昨日(T-1) | task（事件型） |

- 采集顺序固定为上表顺序（脚本内 `ORDER`）。
- **事件型表**（问题订单/评价/售后）当天可能没有任何事件，平台返回"无数据/无有效数据"，脚本记为 `no_data`（状态 ○），**属正常业务事实，不算失败**。

## 两类表单 gen1 / gen2

- **gen1**：有 ant 日历区间控件（`.ant-calendar-range-picker-input`，两个输入框=开始/结束）。daily 直接读预填值，不点击。
- **gen2**（仅两张流量新表）：无日历，用三组单选（统计方式 / 数据粒度 / 时间周期）。daily 需按 **label 文本**点选：
  - 统计方式（日期维度）：分天（不要选"汇总/分时"）
  - 数据粒度：分门店（不要选"汇总/分省市"）
  - 时间周期：昨日
  - 「对比数据」「商圈同行」保持"不导出"。
  - 注意：gen2 这些 radio 的 `value` 有重复（多个 0/1），**不能按 value 定位，必须按可见 label 文本点**。

### 指标勾选（必做）

门店财务明细默认只勾「商家ID/商家名称/省份/城市」4 个默认列、商品数据默认也不全；不勾业务指标直接下载会 toast「请至少勾选一个非默认数据指标」。脚本逻辑：检测到存在未选中 checkbox 就点「全选」；其余表默认已全选，跳过。

## 两种导出模式 task / direct

点下载后弹窗文案决定模式，脚本自动识别分流：

**判定顺序（重要）**：先检查 direct 特征文案（"不会在【下载列表】"或"浏览器下载记录"），再检查 task 特征（"创建成功"+"下载列表"）。避免弹窗同时包含两类关键词时误判。

1. **task（异步任务）**：弹窗含「导出任务创建成功…在【下载列表】查看」。
   - 关闭该弹窗 → 切到「下载列表」页签 → 轮询表格 `tr`，按文件名关键字 + 操作时间匹配最新行 → 点行内 `a.a-default-color`「下载」（其 href 为空，靠点击事件触发，用 Playwright `expect_download` 捕获）。
   - 下载列表文件平台只保留 **7 天**；同表同日重复导出平台会幂等去重（直接命中已有任务）。
2. **direct（直接下载）**：弹窗含「不会在【下载列表】中展示…请在浏览器下载记录获取」。
   - 点「我知道了」后浏览器直接触发下载，用 `expect_download` 捕获即可，无需进下载列表。

## 下载按钮的三种 DOM

不同表的"下载"按钮类名不统一，脚本用「类名 + 精确文本」双保险匹配（排除顶部"报表下载/下载列表"页签）：
- `div.download-btn`，文本"下载数据"
- `a.down-text`，文本"下载报表"
- 无类名 `button`，文本"下载报表"（售后订单表）

## 数据文件与编码

- 原始落盘：`<数据根>/raw/<数据日期>/<报表名>_<日期>.csv`，日期目录用数据业务日期（评价表会落在 T-2 目录）。
- 编码：平台导出为 **GBK** CSV（脚本兼容 xlsx 魔数与 UTF-8 回退）；日期列多为紧凑格式 `20260914`。
- 总表：`<数据根>/master/by_table/<报表名>.csv`，UTF-8-BOM，比原始表多一列 `_采集日期`，按业务时间列升序；同采集日分区整体替换 + 行级去重，重复跑不会累加；表头差异自动合并取并集。
- **整合后自动清理**：原始 CSV 在成功并入总表后自动删除（`cleanup_raw_after_integrate: true`），只保留累积的 CSV 总表和 Excel 总表。

## 已知表头差异

### 售后订单数据（平台字段改版）

**旧版总表字段（21列，含_采集日期）**：
店铺名称、店铺ID、店铺所在城市、下单时间、售后发起时间、展示订单号、订单总金额（元）、退款类型、售后类型、退款原因、成功退款金额（元）、退款商品、退款发起方、退款审核结果、退款处理时长（分钟）、极速退款类型、退货免运费（元）、是否平台售后判为商责、平台售后判责理由、平台售后判责结果、_采集日期

**新版采集字段（19列）**：
店铺名称、店铺ID、店铺所在城市、下单时间、展示订单号、订单总金额（元）、退款类型、售后类型、售后原因、成功退款金额（元）、售后商品、售后发起方、售后审核结果、售后处理时长（分钟）、极速退款类型、退货免运费金额（元）、是否平台售后判为商责、平台售后判责结果、补发配送费（元）

**差异处理**：append_master.py 自动合并取并集，旧版独有字段在新数据中留空，新版独有字段在旧数据中留空。

### 商品数据日期列

商品数据的"日期"列可能出现区间格式（如 `\t20260801-20260831`），这是因为历史采集时选择了日期范围导出。daily模式下应为单日格式（如 `20260915`）。排序时自动提取区间起始日期作为排序键。

## 去重规则

1. **分区替换**：总表带 `_采集日期` 列，同表同采集日重跑时，先删除该采集日的所有行，再追加新数据。
2. **行级去重**：完全相同的业务行（忽略 `_采集日期` 列）只保留最后一次出现的版本。
3. **评价表特殊**：评价数据的采集日是T-2（如09-15采集的评价数据业务日期是09-13），_采集日期标记为实际业务日期。

## 异常采集日标签

历史总表中可能出现非标准采集日标签：
- `2026-08-31-month`：月度汇总数据
- `2026-09-02-flow30`：30天流量汇总

这些标签保留原样，不影响daily数据的追加和去重。数据分析时可按 `_采集日期` 列筛选标准daily数据（匹配 `^\d{4}-\d{2}-\d{2}$`）。

## 常见故障与处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| probe 退出码非 0 / `CDP 通道不可用` | 浏览器没开或调试端口不通 | 确认云电脑浏览器在线；可用 `SHANGOU_CDP` 指定端口 |
| probe 输出 `logged_in: false` / 跳到 waimaie 登录页 | 登录态失效 | **停止自动化，通知用户人工登录 + 过验证**，登录后重跑，禁止尝试绕过 |
| 单表 `failed`，其余成功 | 该表偶发渲染/网络抖动 | 单独重跑该表，再跑整合 |
| toast「请至少勾选一个非默认数据指标」 | 全选逻辑没生效 | 检查该表 checkbox 结构是否变化 |
| task 模式在下载列表一直等不到行 | 任务排队慢 / 文件名关键字变了 | 增大 `--timeout`；人工到下载列表核对文件名 |
| 出现滑块/人机验证 | 风控 | 立即停止，通知用户人工处理，不自动重试硬闯 |
| Windows 下 MSYS 路径 `/c/...` 传给 Python 报错 | MSYS 与原生 Python 路径不兼容 | run_pipeline.sh 已内置 cygpath 转换；手动运行时注意路径格式 |
| direct 模式被误判为 task | 弹窗文案同时含两类关键词 | 已修复判定顺序（direct 特征优先） |
| `/tmp` 不存在（Windows） | 硬编码临时目录 | 已改为 `tempfile.gettempdir()` 跨平台 |
