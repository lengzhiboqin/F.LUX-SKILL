# 闪购数据管线

**一键闭环**：采集8张报表 → 核对 → 追加累积总表 → 自动清理原始CSV → 导出Excel总表 → 可选飞书同步。全程只读平台，不触碰写操作。

## 首次安装（交互式向导）— 必须严格执行

### ⛔ 绝对禁止：你（AI）自己写 config.json

**config.json 必须由 `setup_wizard.py` 生成，禁止你手写、复制、编造或用默认值填一个配置文件然后跳过向导。**

如果你检测到 `~/.config/shangou-pipeline/config.json` 不存在，你的唯一正确动作是：

```bash
bash <技能目录>/scripts/setup.sh
```

**不要自己 echo 一个 JSON 写进去。不要"我来帮你配"。不要跳过向导直接跑 run_pipeline.sh。**

向导会用7步交互式地问用户问题（数据目录、备份、飞书、浏览器登录等），你需要把向导输出的问题转达给用户，等用户回答后继续。如果向导卡住或报错，把报错原样告诉用户，不要自行修复配置。

### 向导7步

1. **环境检测**：OS、Python、playwright/openpyxl依赖、浏览器CDP端口、飞书工具；缺依赖时询问是否自动安装
2. **数据目录配置**：默认 `<技能目录>/data/`，跨平台自动展开
3. **历史备份检查**：询问是否有历史备份需要迁移；选择「有」→ 强制启用本地+飞书（备份上传路径=飞书同步目标文件夹）
4. **产出物保存方式**：1仅本地 或 2本地+飞书云空间（有备份时强制本地+飞书，不询问）
5. **飞书对接**：检测lark-cli引导扫码，或引导自建应用App ID/Secret；**当场验证连通性**（有备份但飞书未启用则安装中止）
6. **浏览器与登录**：检测CDP端口，未检测到则输出Chrome启动命令；支持人工浏览器登录或自动短信验证码登录
7. **历史数据初始化**：有备份 → 自动扫描飞书同步文件夹找备份 → 下载 → **验证格式（sheet名匹配标准8表）** → 迁移 → **缺失检测（行数与日期范围）**；无备份 → 引导Excel迁移或回溯采集近30日数据

### 其他安装命令

```bash
bash <技能目录>/scripts/setup.sh --check   # 仅环境检测，不写配置
bash <技能目录>/scripts/setup.sh --show    # 查看当前配置
bash <技能目录>/scripts/setup.sh --feishu  # 仅重新配置飞书
```

## 标准执行流程

前置条件：已通过安装向导配置，Chrome浏览器已登录闪购商家端。

**用 Python 直接调用（跨平台，不依赖shell）：**
```bash
python3 <技能目录>/scripts/run_pipeline.py
```

也可用 bash 薄包装：
```bash
bash <技能目录>/scripts/run_pipeline.sh
```

它依次完成：登录态探测 → 下载 8 张表（daily 模式）→ 核对产出物 → 追加累积总表（幂等）→ 缺失检测 → **清理原始CSV** → 导出 Excel 总表（同名覆盖）→ 可选飞书同步 → 写结构化摘要。

### Windows 特别说明

- **CDP端口用 9333**（不用9222）。Windows上9222常被WorkBuddy/Edge占用且打开mock演练页。
- **启动Chrome命令**（CMD/PowerShell）：
  ```
  "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9333 --user-data-dir="C:\shangou-chrome-profile"
  ```
- 所有脚本都是 Python，不经过 shell 路径转换，避免 Git Bash/MSYS 路径问题。
- 依赖安装：向导自动执行 `pip install -r requirements.txt`，无需手动搜索。

### 退出码与行动

| 退出码 | 含义 | 行动 |
| --- | --- | --- |
| 0 | 管线全部成功 | 读 `last_pipeline.json` 汇报成功摘要 |
| 1 | 部分表下载失败 或 追加总表有警告 | 对失败表补采后重跑，或读摘要排查 |
| 2 | 浏览器不可用或未登录 | 停止并通知用户人工登录，登录后重跑 |
| 3 | 环境错误（缺依赖/未配置） | 运行 setup.sh 或补装依赖 |
| 4 | 美团反爬/人机识别拦截 | 已自动清空cookie并打开登录页，通知用户重新登录后重跑 |

### 反爬机制（v2，2026-09-18优化）

美团闪购商家端有人机识别SDK（rohr）风控，云电脑环境可能被拦截，页面显示"加载失败"。本技能已内置反爬处理：

1. **模拟人类操作导航**：不直接跳转到报表深层URL，先访问商家端首页，等待页面完全加载，模拟人类滚动和停留，再导航到报表页，降低风控触发概率
2. **反爬检测**：自动检测页面是否包含"加载失败"等人机识别关键词，或页面未正常加载（无hashframe且正文过短）
3. **自动恢复**：检测到反爬拦截时，自动清空所有cookie和浏览器缓存，导航到外卖商家端登录页（waimaie.meituan.com），等待用户重新登录
4. **cookie有效期提醒**：cookie有效期一般7-15天，配置文件中记录`last_login_time`，超过10天时自动提醒建议重新登录
5. **退出码4**：反爬拦截时以退出码4退出，调度器可据此判断需要请求用户接管浏览器重新登录

### 单表补采（某张表失败时）

```bash
python3 <技能目录>/scripts/shangou_report_download.py download --report <表名> --daily --out "<数据目录>/raw"
```

补采成功后重跑 `run_pipeline.sh` 即可自动并入总表。

## 产出物结构

```
<技能目录>/data/
├── raw/<数据日期>/<报表名>_<日期>.csv   # 临时原始报表（整合后自动清理）
├── master/
│   ├── by_table/
│   │   ├── 门店财务明细.csv             # UTF-8-BOM，带 _采集日期 列，按时间升序
│   │   ├── 门店成交明细.csv
│   │   ├── 商品数据.csv
│   │   ├── 问题订单数据.csv
│   │   ├── 流量明细(新).csv
│   │   ├── 流量渠道明细(新).csv
│   │   ├── 评价数据.csv
│   │   ├── 售后订单数据.csv
│   │   └── _update_log.csv             # Excel更新日志
│   └── last_pipeline.json              # 最近一次管线结构化结果
└── F.LUX品牌数据汇总表.xlsx            # 最终交付物（同名覆盖，只保留一份）
```

- **原始数据自动清理**：成功并入总表后自动删除 `raw/<日期>/`，不占空间
- **Excel 同名覆盖**：不保留历史版本，永远只有一份最新总表
- **飞书同名覆盖**：上传飞书时也是同名覆盖，云端只保留一份
- 普通表数据日期为昨日(T-1)，评价表为前日(T-2)，属平台正常行为
- 事件型表（问题订单/评价/售后）当天无数据时记为 `no_data`，不算失败

## 关键行为约定

- **幂等追加**：同表同采集日重跑时该分区整体替换，再行级去重；可反复跑不重复。
- **表头自动合并**：新采集数据与总表表头不一致时自动取并集、缺失字段留空，不拒收。
- **评价表 T-2**：评价数据采集日对应业务日期是前天，属正常。
- **事件型表**：问题订单/评价/售后当天无事件为空属正常，不算失败。
- **时间升序**：每张总表按各自时间列排序。
- **编码**：原始CSV为GBK自动判别读取；总表统一UTF-8-BOM。
- **Windows 兼容**：内置 MSYS 路径转换（cygpath）、跨平台临时目录（tempfile）、导出模式判定修正。

## 缺失数据补齐

`run_pipeline.sh` 自动检测总表日期连续性并报告缺失日期。补齐方式：

1. **缺失日期有原始CSV**：直接重跑 `append_master.py` 自动并入。
2. **缺失日期无原始CSV**：用采集脚本回溯采集该日期，再重跑管线。
3. **新环境无总表**：如有备份Excel，运行 `setup.sh --excel <文件>` 迁移；否则逐日采集生成新总表。

## 与上下游技能的联动

- **下游（数据分析技能）**：读取 `data/master/by_table/` 下的 CSV 总表作为数据源，或读取 Excel 总表。总表带 `_采集日期` 列，可按采集日做环比/同比。
- **未来升级**：CSV 总表可升级为 SQLite/数据库文件，直接对接其他分析技能。

## 挂载为定时任务

用 `doubao-cron-scheduler` 创建周期任务，任务 query 写明：调用本技能运行 `run_pipeline.sh`，按退出码与 `last_pipeline.json` 汇报；退出码 2（未登录）或 1（补采后仍失败）时通知用户人工介入。建议每日上午运行（昨日数据已稳定生成后）。
