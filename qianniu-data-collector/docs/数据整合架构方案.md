# F.LUX品牌数据整合架构方案

> 闪购端 + 牵牛花端 数据整合设计
> 目标：建立统一数据底座，支撑后续门店诊断分析

---

## 一、整体架构设计

### 三层数据架构

```
┌─────────────────────────────────────────┐
│  数据应用层（Analysis Layer）            │
│  门店诊断报告、经营分析、预警监控        │
├─────────────────────────────────────────┤
│  数据集市层（Marts Layer）               │
│  按主题组织：门店主题、商品主题、订单主题 │
├─────────────────────────────────────────┤
│  数据整合层（Integration Layer）         │
│  门店映射、字段统一、清洗标准化          │
├─────────────────────────────────────────┤
│  原始数据层（Raw Layer）                 │
│  按日按系统存储原始文件，不做修改        │
└─────────────────────────────────────────┘
```

---

## 三、数据整合层（Integration Layer）

### 3.1 核心主数据：门店映射表

**问题**：闪购端45家门店 vs 牵牛花端50家门店，仅25家名称完全一致

**解决方案**：建立门店映射表

| 标准门店ID | 标准门店名称 | 闪购端名称 | 牵牛花端名称 | 城市 | 状态 |
|-----------|-------------|-----------|-------------|------|------|
| FLUX001 | F.LUX国际美妆集合店（华晨店） | F.LUX国际美妆集合店（华晨店） | F.LUX国际美妆集合店（华晨店） | 株洲 | 正常 |
| FLUX002 | F·LUX国际美妆集合店（桂林象山店） | F·LUX国际美妆集合店（桂林象山店） | F.LUX国际美妆集合店（桂林象山店） | 桂林 | 正常 |
| ... | ... | ... | ... | ... | ... |

**映射规则**：
1. 先做名称归一化（去掉空格、统一标点、统一品牌名）
2. 再做模糊匹配（编辑距离、关键词匹配）
3. 人工确认匹配结果
4. 建立永久映射表

### 3.2 字段标准化

**时间字段统一**：
- 所有表统一使用 `数据日期`（YYYY-MM-DD）
- 区分 `数据日期`（业务数据日期）和 `采集日期`（数据入库日期）

**门店字段统一**：
- 所有表统一使用 `标准门店ID` 和 `标准门店名称`
- 原始名称保留在 `原始门店名称` 字段中

**金额字段统一**：
- 单位统一为元（牵牛花订单API是分，需要÷100）
- 统一命名：`销售额`、`实付金额`、`退款金额`等

## 四、数据集市层（Marts Layer）

### 4.1 按主题组织

#### 主题1：门店日表（store_daily）
**粒度**：门店×日
**来源**：
- 闪购端：门店财务明细、门店成交明细、流量明细
- 牵牛花端：门店经营指标、门店流量、门店商品指标明细、配送指标明细、门店营业时长

**核心字段**：
```
数据日期 | 标准门店ID | 标准门店名称
--- 经营指标 ---
有效订单数 | 有效订单金额 | 客单价 | 商品原价销售额 | 包装费 | 配送费
--- 流量指标 ---
曝光人数 | 入店人数 | 加购人数 | 下单人数 | 曝光-入店率
--- 商品指标 ---
商品动销率 | 全部商品数 | 缺货数量 | 缺勤数量 | 缺勤损失
--- 配送指标 ---
配送订单数 | 配送超时率 | 单均配送距离 | 单均配送成本
--- 营业指标 ---
营业时长 | 缺勤时长 | 营业状态
--- 财务指标 ---
收入 | 成本 | 毛利 | 净利润
```

#### 主题2：商品日表（product_daily）
**粒度**：商品×日
**来源**：
- 闪购端：商品数据、流量渠道明细
- 牵牛花端：商品流量、品类分析、门店商品指标明细

**核心字段**：
```
数据日期 | 标准门店ID | 商品ID | 商品名称 | 品类
--- 销售指标 ---
销量 | 销售额 | 实付金额 | 退款金额
--- 流量指标 ---
曝光量 | 入店量 | 加购量 | 下单量 | 转化率
--- 库存指标 ---
库存数量 | 缺货状态 | 缺勤状态
```

#### 主题3：订单明细表（order_detail）
**粒度**：订单×商品
**来源**：
- 闪购端：商品数据、问题订单数据、售后订单数据
- 牵牛花端：订单API

**核心字段**：
```
订单编号 | 下单时间 | 标准门店ID | 商品ID | 商品名称
订单金额 | 实付金额 | 退款金额 | 订单状态 | 配送状态
退款原因 | 售后类型 | 评价内容 | 评分
```

#### 主题4：评价表（review）
**粒度**：评价×订单
**来源**：闪购端评价数据

**核心字段**：
```
评价ID | 订单编号 | 标准门店ID | 评价时间 | 评分 | 评价内容 | 追评内容
```

## 五、技术实现方案

### 方案A：SQLite数据库（推荐）

**优点**：
- 单文件，易备份
- 支持SQL查询，方便分析
- 支持索引，查询快
- Python原生支持

**表结构**：
```sql
-- 门店映射表（主数据）
CREATE TABLE store_mapping (
    store_id TEXT PRIMARY KEY,
    store_name_std TEXT,
    store_name_shangou TEXT,
    store_name_qianniu TEXT,
    city TEXT,
    status TEXT
);

-- 门店日表
CREATE TABLE store_daily (
    date TEXT,
    store_id TEXT,
    -- 经营指标
    order_count INTEGER,
    gmv REAL,
    avg_order_value REAL,
    -- 流量指标
    exposure_count INTEGER,
    visit_count INTEGER,
    -- ... 其他指标
    PRIMARY KEY (date, store_id)
);

-- 商品日表
CREATE TABLE product_daily (
    date TEXT,
    store_id TEXT,
    product_id TEXT,
    product_name TEXT,
    category TEXT,
    sales_count INTEGER,
    sales_amount REAL,
    -- ... 其他指标
    PRIMARY KEY (date, store_id, product_id)
);

-- 订单明细表
CREATE TABLE order_detail (
    order_id TEXT,
    order_time TEXT,
    store_id TEXT,
    product_id TEXT,
    product_name TEXT,
    amount REAL,
    status TEXT,
    -- ... 其他字段
    PRIMARY KEY (order_id, product_id)
);
```

### 方案B：CSV文件按主题组织

**优点**：
- 简单直观
- 可用Excel直接打开
- 易迁移

**缺点**：
- 查询慢
- 关联麻烦
- 数据量大了性能差

**目录结构**：
```
data/marts/

│   ├── product_daily_2026-09.csv

│   ├── order_detail_2026-09.csv
│   └── ...

    ├── review_2026-09.csv
```

## 六、实施步骤

### 第一步：建立门店映射表
1. 导出两边所有门店名称
2. 做名称归一化和模糊匹配
3. 人工确认匹配结果
4. 建立永久映射表

### 第二步：数据入库脚本
1. 写一个统一的入库脚本
2. 读取每天的原始数据
3. 做字段映射和清洗
4. 写入SQLite数据库

### 第三步：数据质量校验
1. 校验门店映射覆盖率
2. 校验数据完整性（每天的表是否齐全）
3. 校验数据合理性（数值范围、环比波动）

### 第四步：数据分析接口
1. 提供统一的查询接口
2. 支持按日期、门店、商品等维度查询
3. 为后续分析技能提供数据支持

## 七、索引设计

### 门店日表索引
- 主键：(date, store_id)
- 索引：store_id, date

### 商品日表索引
- 主键：(date, store_id, product_id)
- 索引：product_id, category, date

### 订单明细表索引
- 主键：(order_id, product_id)
- 索引：store_id, order_time, product_id

## 八、后续扩展

### 新增表的接入流程
1. 原始数据采集到raw层
2. 在整合层做字段映射
3. 写入对应的数据集市表
4. 更新数据字典文档

### 数据分析技能的数据调用方式
```python
# 示例：查询某门店某周的经营数据
SELECT * FROM store_daily 
WHERE store_id = 'FLUX001' 
  AND date BETWEEN '2026-09-15' AND '2026-09-21'
```
