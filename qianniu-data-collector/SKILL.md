# 牵牛花数据采集 Skill

F.LUX 品牌牵牛花中台（美团零售外卖多门店管理系统）数据采集工具。全程只读，不触碰任何写操作。

## 首次安装（交互式引导）— 必须严格执行

### ⛔ 绝对禁止：AI 自己写配置文件

配置必须由 `setup_wizard.py` 生成，禁止手写、复制、编造或用默认值填配置然后跳过向导。

如果检测到 `~/.config/qianniu-collector/config.json` 不存在，唯一正确动作是：

```bash
bash <技能目录>/scripts/setup.sh
```

向导会交互式询问（数据目录、浏览器登录、备份等），把向导问题转达给用户，等回答后继续。向导卡住或报错时把错误原样告诉用户，不要自行修复配置。

### 向导核心步骤

1. **环境检测**：OS、Python、playwright/openpyxl 依赖、浏览器 CDP 端口
2. **数据目录配置**：默认 `<技能目录>/data/`
3. **浏览器与登录**：检测 CDP 端口，未检测到则输出 Chrome 启动命令；引导用户人工登录牵牛花中台
4. **登录验证**：登录成功后访问首页确认门店范围为 F.LUX 46 店
5. **历史数据初始化**：引导是否回溯采集近 30 日数据

详见 [references/setup_guide.md](references/setup_guide.md)。

## 标准执行流程

前置条件：已通过安装向导配置，Chrome 浏览器已登录牵牛花中台。

```bash
python3 <技能目录>/scripts/run_collector.py
```

依次完成：登录态探测 → 采集 6 条数据路径 → 核对产出物 → 按日归档落盘 → 缺失检测 → 写结构化摘要。

### 退出码与行动

| 退出码 | 含义 | 行动 |
|--------|------|------|
| 0 | 全部采集成功 | 读 `last_collect.json` 汇报成功摘要 |
| 1 | 部分路径采集失败 | 对失败路径补采后重跑，或读摘要排查 |
| 2 | 浏览器不可用或未登录 | 停止并通知用户人工登录，登录后重跑 |
| 3 | 环境错误（缺依赖/未配置） | 运行 setup.sh 或补装依赖 |

## 6 条数据路径（采集顺序）

详细技术说明（API 参数、页面 URL、导出方式、字段清单）见 [references/data_paths.md](references/data_paths.md)。

| 序号 | 数据类型 | 获取方式 | 粒度 | 预计耗时 |
|------|---------|---------|------|---------|
| 1 | 实时/历史订单 | API 调用 `newQueryList` | 门店×小时×SPU | 3-5 分钟 |
| 2 | 门店当日经营指标 | 首页→门店明细导出 | 门店×日 | 1 分钟 |
| 3 | 门店流量数据 | 流量概览→门店流量排行导出 | 门店×日 | 1 分钟 |
| 4 | 商品流量数据（三Tab） | 商品流量分析导出（全部/店外/店内） | SPU×日 | 3 分钟 |
| 5 | 品类销售+缺勤损失 | 品类分析导出（需先选指标） | 品类×日 | 1 分钟 |
| 6 | 门店在售商品 | 门店商品页读取（渠道库存列） | 门店×SKU | 5 分钟 |

### 采集纪律

1. **纯查看模式**：严禁任何修改/新增/删除/审核操作；严禁点击"重新申请""取消授权"类按钮
2. **最小数据量验证**：首次采集每条路径用 1 天/1 家店验证导出成功，字段正确后再全量
3. **跨品牌过滤**：所有数据采集后必须过滤，只保留名称含 F.LUX/F·LUX 的门店（剔除觅初）
4. **口径声明**：所有产出文件头部或元数据必须声明"品牌范围：46家 F.LUX/F·LUX 门店（已剔除跨品牌门店：觅初）"
5. **失败重试**：单条路径失败重试 2 次，仍失败则记录错误信息，继续下一条，不阻塞整体

## 产出物结构

```
<技能目录>/data/
├── raw/<数据日期>/
│   ├── 订单API_<日期>.json
│   ├── 门店经营指标_<日期>.csv
│   ├── 门店流量_<日期>.csv
│   ├── 商品流量_全部_<日期>.csv
│   ├── 商品流量_店外_<日期>.csv
│   ├── 商品流量_店内_<日期>.csv
│   ├── 品类分析_<日期>.csv
│   └── 门店在售商品_<日期>.csv
├── master/
│   ├── by_table/
│   │   ├── 订单明细.csv          # 带 _采集日期 列，按时间升序
│   │   ├── 门店经营指标.csv
│   │   ├── 门店流量.csv
│   │   ├── 商品流量.csv
│   │   ├── 品类分析.csv
│   │   └── 门店在售商品.csv
│   └── last_collect.json         # 最近一次采集结构化结果
└── 缺失检测报告_<日期>.md         # 数据缺失/异常检测
```

- **原始数据保留**：`raw/<日期>/` 永久保留，不自动清理（与闪购管线不同，牵牛花数据需要自建历史库）
- **总表幂等追加**：同表同采集日重跑时该分区整体替换，再行级去重
- **时间升序**：每张总表按各自时间列排序
- **编码统一**：总表统一 UTF-8-BOM

## 单表补采（某条路径失败时）

```bash
python3 <技能目录>/scripts/collect_single.py --path <路径编号> --date <YYYY-MM-DD> --out "<数据目录>/raw/<日期>/"
```

路径编号：1=订单API, 2=门店经营指标, 3=门店流量, 4=商品流量, 5=品类分析, 6=门店在售商品。

补采成功后重跑 `run_collector.py` 即可自动并入总表。

## 登录态探测与恢复

```bash
python3 <技能目录>/scripts/check_login.py
```

- 探测接口：`GET /api/v1/isLogined`
- 成功标志：`{"code":0,...}` 且返回用户名
- 失败处理：输出 Chrome 启动命令和登录页面 URL，通知用户人工扫码登录
- 登录后自动重跑探测确认

## 缺失数据补齐

`run_collector.py` 自动检测总表日期连续性并报告缺失日期。补齐方式：

1. **缺失日期有原始CSV**：直接重跑 `append_master.py` 自动并入
2. **缺失日期无原始CSV**：用 `collect_single.py --date <缺失日期>` 回溯采集该日期，再重跑管线
3. **新环境无总表**：如有备份 Excel，运行 `setup.sh --excel <文件>` 迁移；否则逐日采集生成新总表

## 与上下游技能的联动

- **上游**：无（本 Skill 是数据源头）
- **下游（巡店分析技能，待开发）**：读取 `data/master/by_table/` 下的 CSV 总表作为数据源，总表带 `_采集日期` 列，可按采集日做环比/同比
- **平行（闪购数据管线 shangou-data-pipeline）**：两者配合，牵牛花提供实时/流量/缺勤/在售等独有数据，闪购提供财务/成交/评价/售后等经营数据

## 挂载为定时任务

用 `doubao-cron-scheduler` 创建周期任务，任务 query 写明：调用本技能运行 `run_collector.py`，按退出码与 `last_collect.json` 汇报；退出码 2（未登录）或 1（补采后仍失败）时通知用户人工介入。建议每日 14:30 后运行（流量数据 12:00 更新、商品流量 14:00 更新）。
