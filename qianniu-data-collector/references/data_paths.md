# 牵牛花中台 6 条数据路径详细技术说明

> 本文档包含每条路径的获取方式、API 参数、页面 URL、导出操作步骤、字段清单、已知限制和排错方法。
> 仅在具体执行采集或排错时读取，日常运行不需要加载。

---

## 路径1：实时/历史订单数据（API 通道）

### 基本信息
- **获取方式**：API 直接调用（无需浏览器页面操作）
- **接口**：`POST /api/v1/orderfuse/newQueryList`
- **基础域名**：`https://qnh.meituan.com`（或当前登录环境的实际域名）
- **粒度**：门店 × 小时 × SPU
- **支撑目标**：目标1（实时巡店异常判定）、目标4（商品销量聚合）

### 请求参数

```json
{
  "_t": "<毫秒时间戳>",
  "createStartTime": "<当日0点毫秒时间戳>",
  "createEndTime": "<当前时间毫秒时间戳>",
  "pageNo": 1,
  "pageSize": 100
}
```

### 分页处理
- 单页最多 100 条，需循环翻页直到 `orderList` 为空
- 每页间隔 500ms，避免触发限流
- 30 天数据建议按天切片拉取，避免单页数据量过大

### 返回字段（orderList[]）

| 字段 | 类型 | 说明 |
|------|------|------|
| createTime | number | 下单时间（毫秒时间戳） |
| payTime | number | 支付时间（毫秒时间戳） |
| storeName | string | 门店名称 |
| storeId | string | 门店 ID |
| orderStatusDesc | string | 订单状态描述 |
| orderId | string | 订单号 |
| totalPrice | number | 订单总金额 |
| productList[] | array | 商品明细列表 |
| productList[].spuId | string | SPU ID |
| productList[].spuName | string | SPU 名称 |
| productList[].skuId | string | SKU ID |
| productList[].quantity | number | 购买数量 |
| productList[].price | number | 商品单价 |

### 配套接口
- `GET /api/v1/orderfuse/getOrderStatisticsData` — 订单统计汇总
- `POST /api/v1/orderfuse/queryordersubstatuscount` — 订单子状态计数

### 注意事项
- ⚠️ 时间参数为**毫秒时间戳字符串**，不是秒
- ⚠️ 自然日按 **+08:00 零点**取界（北京时间）
- ⚠️ 需携带登录态 Cookie（`token` 等），否则返回未授权
- ⚠️ 30 天全量拉取约 6 批，串行耗时 ~18 分钟，建议并行化（4-6 小时切片+批次并行）

### 排错
- **返回 code != 0**：查看 msg 字段，常见为登录态失效 → 重新登录
- **orderList 为空但实际有单**：检查时间参数是否正确（毫秒 vs 秒），确认门店范围
- **分页到一半报错**：可能触发限流，增加间隔到 1s，或减少 pageSize

## 路径2：门店当日经营指标（页面导出）

### 基本信息
- **获取方式**：浏览器页面操作 + 导出下载
- **页面路径**：首页 → 门店明细
- **页面 URL（hash 路由）**：`#/home`（首页工作台）
- **粒度**：门店 × 日
- **支撑目标**：目标1（人工复核通道，与 API 数据交叉验证）
- **任务ID样例**：4268579

### 操作步骤

1. 登录后进入首页工作台
2. 找到「门店明细」区域/卡片
3. 点击「导出」按钮
4. **无需选择指标**，直接确认导出
5. 跳转到「下载中心」/「任务中心」轮询任务状态
6. 任务完成后下载文件

### 导出任务轮询接口
```
POST /api/v1/task/queryTasks
Payload: {"pageNo":1,"pageSize":10,"queryType":"TAB_DOWNLOAD"}
```
- 按 `taskName` + `opTime` 匹配新任务
- `executingState === '已完成'` 后取 `oprList[0].url` 下载

### 字段清单（约 12 列）

| 字段 | 说明 |
|------|------|
| 门店名称 | F.LUX 门店名 |
| 门店 ID | 系统内部 ID |
| 当日订单量 | 当日有效订单数 |
| 当日营业额 | 当日实付金额 |
| 客单价 | 营业额 / 订单量 |
| （其他经营指标） | 以实际导出为准 |

### 注意事项
- ⚠️ 导出无需选指标，直接点击导出即可
- ⚠️ 无头浏览器普通下载可能被静默拦截，需用 `fetch(exportData URL, {credentials:'include'})` → arrayBuffer → base64 → 解码落盘
- ⚠️ 导出文件为 GBK 编码，读取时需自动判别

### 排错
- **导出按钮点击无反应**：检查页面是否完全加载，等待 antd 动画完成
- **任务中心看不到新任务**：可能 taskName 匹配规则不对，扩大时间范围查找
- **下载链接 403**：下载链接有时效，任务完成后尽快下载；需携带 Cookie

## 路径3：门店流量数据（页面导出）

### 基本信息
- **获取方式**：浏览器页面操作 + 导出下载
- **页面路径**：数据 → 流量概览 → 门店流量排行
- **页面 URL（hash 路由）**：`#/data/flow-overview`
- **粒度**：门店 × 日
- **支撑目标**：目标2（流量 vs 转化诊断）
- **任务ID样例**：4269399

### 操作步骤

1. 进入「数据」→「流量概览」页面
2. 切换到「门店流量排行」Tab
3. 确认时间范围为目标日期（默认昨日）
4. 点击「导出」按钮
5. **无需选择指标**，直接确认导出
6. 任务中心轮询并下载

### 字段清单（约 10 列，含「全部」行=品牌均值）

| 字段 | 说明 |
|------|------|
| 门店名称 | 含「全部」行=品牌所有门店汇总 |
| 曝光人数 | 商品被展示的用户数 |
| 曝光次数 | 商品被展示的次数 |
| 入口人数 | 点击进入店铺的用户数 |
| 入口次数 | 点击进入店铺的次数 |
| 下单人数 | 完成下单的用户数 |
| 下单订单数 | 有效订单数 |
| 下单转化率 | 下单人数 / 入口人数 |
| 客单价 | 实付金额 / 有效订单 |
| （其他流量指标） | 以实际导出为准 |

### 关键用法
- **品牌均值**：导出文件中的「全部」行即为品牌均值，对比基准用这一行，不要自己算平均
- **流量漏斗**：曝光 → 入口 → 下单，三级漏斗可诊断流量问题 vs 转化问题

### 注意事项
- ⚠️ **最多查近 2 周数据**，超过 2 周的数据平台不提供 → 必须每日落盘自建历史库
- ⚠️ **商圈同行均值本中台不提供**，对比基准只能用品牌均值（「全部」行）
- ⚠️ 页面自带「建议关注」机制，自动标注异常门店及归因文案，可作为第一层初判
- ⚠️ 导出文件为 GBK 编码

### 排错
- **「全部」行缺失**：检查是否筛选了特定门店，清除筛选条件后重新导出
- **数据日期不对**：检查页面日期选择器，确认是目标日期（T-1）
- **导出字段不全**：可能页面有「指标选择」，确认所有指标都已勾选

## 路径4：商品流量数据（页面导出，三 Tab）

### 基本信息
- **获取方式**：浏览器页面操作 + 导出下载（三个 Tab 独立导出）
- **页面路径**：数据 → 商品流量分析
- **页面 URL（hash 路由）**：`#/data/product/flow-performance`
- **粒度**：SPU × 日
- **支撑目标**：目标3（商品缺失比对）
- **任务ID样例**：全部 4269632、店内 4271746

### 三个 Tab 说明

| Tab 名称 | 含义 | 用途 |
|---------|------|------|
| **全部** | 店内+店外汇总流量 | 品牌整体商品流量排名 |
| **店外** | 顾客还没进店时刷到商品的流量（搜索/推荐/榜单等） | 诊断"拿不到平台流量"的问题 |
| **店内** | 顾客进店后看到商品的流量（店内搜索/分类/推荐等） | 诊断"店内商品曝光分配"问题 |

### 操作步骤（每个 Tab 重复一次）

1. 进入「数据」→「商品流量分析」页面
2. 切换到目标 Tab（全部/店外/店内）
3. 确认时间范围为目标日期
4. **如需单店数据**：使用门店筛选器选择目标门店
5. 点击「导出」按钮
6. **无需选择指标**，直接确认导出
7. 任务中心轮询并下载
8. 文件名标注 Tab 类型（如 `商品流量_全部_日期.csv`）

### 字段清单（约 30 列，1573 SPU）

**商品信息类：**
| 字段 | 说明 |
|------|------|
| SPU ID | 商品 SPU 标识 |
| SPU 名称 | 商品名称 |
| 店内分类 | 门店内部分类（一级/二级） |
| 三级类目 | 美团渠道类目体系 |

**流量指标类（本期/环比/波动各一套）：**
| 字段 | 说明 |
|------|------|
| 曝光人数 | 商品被展示的用户数 |
| 曝光次数 | 商品被展示的次数 |
| 点击人数 | 点击商品的用户数 |
| 点击次数 | 点击商品的次数 |
| 下单人数 | 购买该商品的用户数 |
| 下单订单数 | 包含该商品的订单数 |
| 点击率 | 点击人数 / 曝光人数 |
| 下单转化率 | 下单人数 / 点击人数 |
| 商品转化率 | 下单人数 / 曝光人数 |

### 关键用法
- **品牌高流量 SPU 集合**：全部 Tab 导出中，曝光 > 阈值的 SPU 即为品牌高流量商品
- **门店缺失 SPU**：品牌高流量集合 - 该店有曝光的 SPU 集合 = 缺失高流量商品
- **店内 vs 店外拆分**：店外曝光低 → 商品拿不到平台流量（需优化标题/主图/价格）；店内曝光低 → 店内分配问题（需调整分类/排序）

### 注意事项
- ⚠️ **仅含美团渠道流量数据**，饿了么 4 店数据不可见
- ⚠️ 三个 Tab **必须分别导出**，不能一次导出全部
- ⚠️ 单店查询需在页面筛选器中选择门店，导出的是该店数据
- ⚠️ 商品流量数据预计 **14:00 更新**，采集需在 14:30 后
- ⚠️ 导出文件为 GBK 编码

### 单品分析补探（可选）
- 路由：`#/data/product/flow-analysis?category_name=<类目路径>&date=<日期参数>`
- 也可从商品流量分析列表行点「单品分析」进入
- 内容：商品级 6 指标 + 三个转化率 + 趋势图（整体/分来源）+ 门店选择器
- 同样含全部/店外/店内三 Tab

### 排错
- **Tab 切换后数据不刷新**：等待页面加载完成，antd Tab 切换有动画
- **导出的是全部店数据不是单店**：确认筛选器中已选择目标门店，且筛选已生效
- **SPU 数量明显偏少**：检查时间范围，可能选了太短的时间段

## 路径5：品类销售 + 缺勤损失（页面导出）

### 基本信息
- **获取方式**：浏览器页面操作 + 导出下载（**需先在页面选择指标**）
- **页面路径**：数据 → 品类分析
- **页面 URL（hash 路由）**：`#/data/category-analysis`
- **粒度**：一级/二级品类 × 日（支持三级下钻）
- **支撑目标**：目标4（补货策略优先级，缺勤损失金额化）
- **任务ID样例**：4271205

### 操作步骤（关键：必须先选指标）

1. 进入「数据」→「品类分析」页面
2. 确认时间范围为目标日期
3. **在页面上方选择具体指标**（如「总销售收入」）——这一步必须做，否则导出可能为空或字段不全
4. 点击「导出」按钮
5. 确认导出
6. 任务中心轮询并下载

### 字段清单（约 11 列，39 行=一级品类）

| 字段 | 说明 |
|------|------|
| 一级品类 | 品类名称 |
| 商品原价销售额 | 按原价计算的销售额 |
| 总销售收入 | 实付销售收入 |
| 订单数 | 有效订单数 |
| 总销量 | 商品销售件数 |
| 在售商品数 | 当前在售的 SPU 数量 |
| 动销商品数 | 有销量的 SPU 数量 |
| 商品动销率 | 动销商品数 / 在售商品数 |
| 毛利额 | 销售毛利 |
| 毛利率 | 毛利额 / 总销售收入 |
| **商品缺勤损失** | **缺货导致的损失金额（核心指标）** |

### 三级下钻
- 页面支持：一级品类 → 二级品类 →（商品品类明细）三级下钻
- 如需更细粒度数据，在页面点击品类名称下钻后再导出

### 关键用法
- **缺勤损失金额化**：「商品缺勤损失」列直接量化了每个品类因为缺货损失了多少钱，是补货优先级的核心排序依据
- **动销率**：动销商品数 / 在售商品数，低动销率品类可能存在大量滞销商品
- **品类对比**：各品类的销售额/销量/毛利对比，识别品牌核心品类

### 注意事项
- ⚠️ **必须先在页面选择指标（如「总销售收入」），再点导出**，否则导出可能失败或字段不全
- ⚠️ 双类目体系：店内分类 vs 美团渠道类目，导出时注意区分
- ⚠️ 导出文件为 GBK 编码

### 排错
- **导出文件为空或只有几行**：大概率是没选指标，回到页面选好指标后重新导出
- **缺勤损失列全为 0**：检查时间范围，或确认该品类是否真的无缺勤
- **找不到「商品缺勤损失」字段**：可能需要在指标选择中勾选，确认所有指标都已选中

## 路径6：门店在售商品（页面读取，正路径待打通）

### 基本信息
- **获取方式**：浏览器页面读取（非导出，需逐店遍历）
- **页面路径**：门店商品管理
- **页面 URL（hash 路由）**：`#/ocms/product`
- **粒度**：门店 × SKU
- **支撑目标**：目标3、目标4（真实在售 SPU 集合，覆盖率比对）
- **当前状态**：⚠️ 正路径待打通，原项目用降级方案

### 操作步骤

1. 进入「门店商品」页面（`#/ocms/product`）
2. 选择目标门店
3. 页面展示商品列表，含**渠道库存列**
4. 遍历分页，读取所有商品的：SPU ID、SPU 名称、SKU ID、库存数量、在售状态
5. 库存 > 0 且状态为「在售」的 SKU 即为真实在售商品
6. 逐店重复，汇总所有门店的在售 SPU 集合

### 字段清单

| 字段 | 说明 |
|------|------|
| 门店名称 | 所属门店 |
| SPU ID | 商品 SPU 标识 |
| SPU 名称 | 商品名称 |
| SKU ID | SKU 标识 |
| SKU 规格 | 规格描述 |
| 渠道库存 | 该渠道的库存数量 |
| 在售状态 | 在售/下架/售罄 |
| 分类 | 商品分类 |

### 降级方案（当前使用）
- **逻辑**：近 30 天有销售记录的 SPU ≈ 在售
- **数据来源**：路径1（订单API）的 productList[]
- **问题**：覆盖率系统性偏低（最高仅 48.5%），因为很多在售但没销量的商品被漏掉了
- **文件过重**：降级方案导出文件 1.6MB / 10926 行

### 打通正路径后的收益
- 覆盖率以真实在售口径计算，准确反映门店商品丰富度
- 文件瘦身（只需要汇总+头部门店明细，不需要全量明细）
- 可区分「在售但无库存」和「未上架」两种缺失状态

### 注意事项
- ⚠️ 需逐店遍历，46 家店耗时较长（约 5 分钟）
- ⚠️ 页面可能有分页，需翻页读取全部商品
- ⚠️ 渠道库存列可能需要展开或切换 Tab 才能看到
- ⚠️ 注意区分「在售」和「有库存」：在售但库存=0 = 缺货，未上架 = 完全缺失

### 排错
- **页面加载慢**：商品列表数据量大，等待加载完成后再读取
- **找不到渠道库存列**：可能在「库存」Tab 或需要展开商品详情
- **分页读取重复/遗漏**：记录每页的最后一个 SPU ID，作为下一页的起始标记

## 通用技术备忘

### 页面导航
- hash 路由直跳：`location.hash = '#/data/xxx'`
- 侧边栏折叠时用「搜索菜单」或 fiber 路由提取

### 导出下载（无头浏览器坑）
- 无头浏览器普通下载被静默拦截
- 解决方案：页内 `fetch(exportData URL, {credentials:'include'})` → arrayBuffer → base64 → 解码落盘
- 必须 `awaitPromise: true`

### 任务轮询
```
POST /api/v1/task/queryTasks
Payload: {"pageNo":1,"pageSize":10,"queryType":"TAB_DOWNLOAD"}
```
- 按 `taskName` + `opTime` 匹配新任务
- `executingState === '已完成'` 后取 `oprList[0].url` 下载

### 无头渲染坑
- antd 抽屉/下拉动画会卡在起始帧（offscreen），需强制复位 `transform: translateX(0)`
- 「筛选指标」抽屉在商品销售页 `data=[]` 为上游数据问题，非渲染问题

### 数据口径
- 商品流量数据仅美团渠道
- 流量概览限近 2 周
- 品类分析双类目体系（店内分类/美团渠道类目）
- 所有时间为北京时间 +08:00

### 导出规则汇总
| 页面 | 是否需要选指标 | 导出状态 |
|------|--------------|---------|
| 首页门店明细 | 否 | ✅ 可导出 |
| 门店流量排行 | 否 | ✅ 可导出 |
| 商品流量分析 | 否 | ✅ 可导出（三Tab分别导） |
| 品类分析 | **是（必须先选）** | ✅ 可导出 |
| 订单列表 | - | ❌ 不可用（用 API 替代） |
| 商品销售页 | - | ❌ 受限（data=[]，用品类分析+订单API替代） |
