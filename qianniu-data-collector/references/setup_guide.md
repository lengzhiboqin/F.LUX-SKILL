# 牵牛花数据采集 Skill · 首次安装引导指南

> 本文档详细说明首次安装的交互式向导流程、每一步的目的和用户需要配合的操作。
> 仅在首次安装或重新配置时读取。

---

## 安装前置条件

| 依赖 | 最低版本 | 说明 |
|------|---------|------|
| Python | 3.8+ | 运行采集脚本 |
| Chrome/Chromium 浏览器 | 最新版 | 登录牵牛花中台 + 页面导出 |
| 远程调试端口 | 9222 或 9333 | 浏览器需以 `--remote-debugging-port` 启动 |
| 网络 | 可访问 qnh.meituan.com | 牵牛花中台域名 |
| 商家账号 | F.LUX 牵牛花中台账号 | 需有数据查看权限 |

---

## 安装向导 7 步流程

### Step 1：环境检测

**目的**：确认运行环境满足最低要求，缺依赖时自动安装。

**检测项**：
- OS 类型（Linux/Windows/macOS）
- Python 版本（≥3.8）
- 必需 Python 包：`playwright`、`openpyxl`、`pandas`、`requests`
- Chrome/Chromium 浏览器是否安装
- 远程调试端口是否可连接（9222/9333）
- 网络连通性（能否访问 qnh.meituan.com）

**用户配合**：
- 缺依赖时询问是否自动安装，回答「是」即可
- 如果浏览器未启动，向导会输出启动命令，需用户手动执行

---

### Step 2：数据目录配置

**目的**：确定原始数据和总表的存储位置。

**默认值**：`<技能目录>/data/`

**目录结构**：
```
data/
├── raw/           # 原始数据（按日期归档，永久保留）
├── master/        # 累积总表（按表存储，幂等追加）
└── logs/          # 采集日志
```

**用户配合**：
- 直接回车使用默认路径，或输入自定义路径
- 建议使用默认路径，便于后续 Skill 自动查找

---

### Step 3：浏览器与登录配置

**目的**：配置浏览器远程调试连接，并引导用户登录牵牛花中台。

#### 3.1 浏览器启动

如果检测到远程调试端口未开启，向导会输出启动命令：

**Linux：**
```bash
google-chrome --remote-debugging-port=9222 --user-data-dir=/home/user/qianniu-chrome-profile
```

**Windows：**
```cmd
"C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9333 --user-data-dir="C:\qianniu-chrome-profile"
```

**用户配合**：
- 复制命令在终端执行，启动浏览器
- 启动后回到向导，按回车继续检测

#### 3.2 登录牵牛花中台

浏览器启动后，向导会自动打开登录页面：
- URL：`https://qnh.meituan.com`（或实际登录域名）
- 页面：美团商家登录页

**用户配合**：
- 在浏览器中手动完成登录（账号密码/短信验证码/扫码）
- 登录成功后，确认进入牵牛花中台首页
- 回到向导，按回车继续

#### 3.3 登录验证

向导自动验证登录态：
- 调用 `GET /api/v1/isLogined`
- 检查返回 `code === 0` 且包含用户名
- 访问首页，确认门店列表中包含 F.LUX 门店

**验证失败处理**：
- 提示用户重新登录
- 最多重试 3 次，仍失败则中止安装

---

### Step 4：品牌范围确认

**目的**：确认采集范围为 F.LUX 46 家门店，剔除跨品牌门店。

**自动检测**：
- 从首页门店列表中提取所有门店名称
- 过滤名称含 `F.LUX` 或 `F·LUX` 的门店
- 标记不含 F.LUX 的门店（如「觅初」）为待剔除

**用户配合**：
- 向导展示检测到的门店列表和数量
- 确认「46 家 F.LUX 门店，已剔除觅初等跨品牌门店」
- 如有出入，手动调整门店清单

**配置写入**：
- 门店白名单写入配置文件
- 后续所有采集自动过滤，只保留白名单门店

---

### Step 5：采集路径验证

**目的**：用最小数据量验证 6 条数据路径均可正常采集。

**验证方式**：
- 每条路径用「1 天数据 + 1 家门店」试采集
- 验证导出成功、字段正确、文件可读取
- 记录每条路径的耗时和字段清单

**验证顺序**：
1. 路径1：订单API（最快，不依赖页面导出）
2. 路径2：门店经营指标导出
3. 路径3：门店流量导出
4. 路径4：商品流量导出（三Tab）
5. 路径5：品类分析导出（需先选指标）
6. 路径6：门店在售商品读取（最慢，逐店遍历）

**用户配合**：
- 验证过程中如遇页面弹窗/验证码，手动处理
- 验证完成后，向导展示每条路径的状态（✅成功/⚠️部分失败/❌失败）
- 对失败路径，可选择「跳过」或「重试」

**注意**：路径6（门店在售商品）正路径待打通，验证时可能使用降级方案，此为正常情况。

---

### Step 6：历史数据初始化（可选）

**目的**：决定是否回溯采集历史数据，建立历史库。

**选项**：
1. **不回溯**：从今天开始采集，历史数据后续逐日累积
2. **回溯近 7 天**：采集最近 7 天数据（推荐，可支撑近7日基线计算）
3. **回溯近 30 天**：采集最近 30 天数据（完整历史库，耗时较长）
4. **从备份迁移**：如有历史数据备份，直接导入

**用户配合**：
- 选择回溯范围（推荐「近 7 天」）
- 回溯过程中保持浏览器登录态
- 回溯完成后，向导展示数据完整性报告

**注意**：
- 流量数据仅近 2 周可用，超过 2 周的流量数据无法回溯
- 订单 API 可回溯 30 天
- 回溯期间如遇登录态失效，需重新登录后继续

---

### Step 7：配置完成与定时任务建议

**目的**：写入最终配置，给出定时任务建议。

**配置写入**：
- `~/.config/qianniu-collector/config.json`
- 包含：数据目录、浏览器端口、门店白名单、采集路径配置、历史回溯范围

**定时任务建议**：
- 执行时间：**每日 14:30 后**（流量数据 12:00 更新、商品流量 14:00 更新）
- 执行命令：`python3 <技能目录>/scripts/run_collector.py`
- 通知方式：采集完成后通过企微/飞书推送摘要
- 失败处理：退出码 2（未登录）或 1（补采后仍失败）时通知人工介入

**用户配合**：
- 确认是否现在创建定时任务（推荐使用 `doubao-cron-scheduler`）
- 如暂不创建，记录命令供后续手动执行

## 安装完成验证

安装完成后，执行以下验证：

```bash
# 1. 检查配置文件
python3 <技能目录>/scripts/check_config.py

# 2. 检查登录态
python3 <技能目录>/scripts/check_login.py

# 3. 试采集一天数据（验证全流程）
python3 <技能目录>/scripts/run_collector.py --date <昨日日期> --dry-run
```

全部通过后，安装完成。

## 常见问题

### Q：浏览器启动后远程调试端口连不上？
A：确认启动命令中 `--remote-debugging-port` 参数正确，且没有其他程序占用该端口。Windows 上建议用 9333（9222 常被占用）。

### Q：登录后总是提示登录态失效？
A：确认使用了独立的 `--user-data-dir`，不要和日常浏览共用 Chrome 配置文件。登录成功后不要关闭浏览器。

### Q：某条数据路径总是导出失败？
A：检查 `references/data_paths.md` 中该路径的注意事项，特别是「必须先选指标」类的操作要求。如仍失败，记录错误信息，可暂时跳过该路径，不影响其他路径采集。

### Q：门店数量不是 46 家？
A：可能有新开门店或闭店，在 Step 4 品牌范围确认时手动调整门店白名单即可。

### Q：历史数据回溯很慢？
A：正常现象。订单 API 30 天数据约需 15-20 分钟，页面导出每条约 1-3 分钟。回溯期间保持浏览器开启，不要操作其他页面。
