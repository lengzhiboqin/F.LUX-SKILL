# 清洗入库模块（第二阶段）

职责：**把已验收原件按固定规则整理、单事务增量入库、独立自检、365 日保留**。
边界：**不打开平台、不自动补采**；只消费清单里列明的原件（**不扫目录、不吃目录残留**）。

## 一、规则是版本化的、逐表声明的

唯一规则来源：`references/cleaning_rules.json`（`rule_version` 随批次写入 `_batch`）。
每张表声明：`load_to_db`、`snapshot`、`business_key`、`date_source`、`channel_scope`、
`drop_cols`、`renames`、`money_cols`、`percent_numeric_cols`、`summary_rule`。

- **19 表全覆盖**；`load_to_db=false` 的两张（门店流量排行、门店流量_分来源）**必须写原因**，
  不静默丢弃。
- 业务含义未决的列**保留原名 + 标 `pending`**，进 `_catalog` 时 `formal_source=null`，
  **不猜值**。
- 想改规则 → 改 JSON 并升 `rule_version`；**不要在代码里写第二套规则**。

清洗做的事（复用 `normalize`）：

| 项 | 规则 |
|---|---|
| 空值 | `-` / `--` / `∞` 等 → 空串，**不填 0** |
| 长编号 | 纯整数文本**保持整数**（不走浮点，末位不丢） |
| 金额 | 统一到分（`round_money`） |
| 百分比 vs 百分点 | `8.16%` → `0.0816`；`2.10pp` → `2.10`，**两者不混用** |
| 汇总行 | 打 `_是否汇总行` 标记，**全店汇总不摊到门店** |
| 门店 | 名称/别名归一后匹配主档 → `门店标准ID`；**匹配不到就留空待核，不猜 ID** |
| 日期 | 牵牛花取**文件名**日期；闪购取**日期列**（`date_source`） |

## 二、去重（逐表声明，不猜）

| 表 | 规则 | 为什么 |
|---|---|---|
| 商品数据 | **短键 + 批次**：短键分组 → 取最新批次 → 保留该批次全部行 | 平台会**回溯修订**；整行当键会把一笔业务算成多笔；只按短键又会丢掉同批次真实多明细 |
| 评价数据 | **逐列非空覆盖** | 同一评价跨批次的字段补全 |
| 售后订单数据 | **只打标记，不丢行** | 按行判定，错位段原样保全 |
| 其余表 | **原样透传** | 实测跨批次重复只在商品数据出现 |

批次标记读 `采集时间`（旧规则写的 `_采集日期` 已被规整阶段丢弃，值并入 `采集时间`）。

## 三、入库语义（三条不变量）

1. **同一事务**写事实 + `_catalog` + `_coverage` + `_lineage` + `_batch`；任一失败**整批回滚**。
2. **修订 = 整组替换**：按「表 + 业务日期集合 + 范围」删除后再插入，**不是**按业务键逐行删。
   原因：源端某组**减少或变为无事件**时，被删掉的键不会出现在新输入里，按业务键删会留下
   **幽灵行**（会多计销量/金额）。空组（`no_data`）也必须能清掉旧组。
3. **快照表**（`商品流量_近30天`）**整表替换**，且拒绝比库内更旧的窗口结束日（榜单不倒退）。

追加语义：新日期/新业务**新增**；同一批次重跑**不增重**；同表/日期/范围的修订**替换**旧结果。

入库前基础校验（不通过则整批拒绝、不写任何一行）：
业务键列必须存在且非空、`validated` 组不得零行、每个来源文件必须有 SHA-256、
事实表**出现新列必须停下人工确认**（不自动补列/重排）。

## 四、独立自检（`selfcheck`）

原则：**独立复算，不复用生产的清洗/去重作答案**；**只读**（`mode=ro` + `query_only`）。

- 从 `_lineage` 定位原件，按规则**独立**把源件算成预期值，再与库内值比对。
- 检查范围：字段/类型/单位/必需值/日期范围 + 值（行数、业务键、真实多明细、长编号、
  金额、百分比/百分点、门店、正式来源、覆盖状态）。
- **全量**与**抽样**两种；抽样固定 `seed`，报告注明**选样规则、数量、范围**，
  不宣称未检查部分全部正确。
- 支持 `--table / --start / --end / --store / --scope`；默认只查本批受影响范围，
  **不默认扫全库**。
- 源件不可用 → 报 `source_unavailable`，**不能冒充值复核通过**。
- 发现异常 → **只报告、不回改**；已提交数据不能声称能回滚，按显式修正批次处理。
- 过期行**只报告不删除**。

```bash
python scripts/flux.py selfcheck --db _data/flux.db --mode full
python scripts/flux.py selfcheck --db _data/flux.db --mode sample \
    --sample-size 200 --seed 20261001 --start 2026-09-01 --end 2026-09-30
python scripts/flux.py selfcheck --db _data/flux.db --table 评价数据 --scope channel:100
```

退出码：`0` 通过 / `1` 发现问题 / `2` 参数或库不可用。

## 五、365 日保留与空间维护

- 以业务日 T 定界：活动库保留**业务日期 T-365 ~ T-1**（含两端共 365 个自然日）。
  例 T=`2026-10-01` → 保留 `2025-10-01 ~ 2026-09-30`。
- **按业务日期**判期，不按文件创建/采集时间；**不因最新数据较旧而把窗口无限前移**；
  闰年也不变。
- 过期**事实**及其**日期型** `_coverage`/`_lineage` 一起清理；
  `_store_master`、`_catalog` 等**非日期型**资料**不误删**。
- 快照表按**窗口结束日**判期，**不裁切**快照内容。
- 每次成功入库**在同一事务内**执行过期清理；另提供**独立维护**入口，供数据未新增时调用。
- **采集失败绝不自动改动旧库。**

```bash
# 先备份 + 出截断预览，再真正清理
python scripts/flux.py retain --db _data/flux.db --today 2026-10-01 \
    --backup-dir _data/_backup --dry-run
python scripts/flux.py retain --db _data/flux.db --today 2026-10-01 \
    --backup-dir _data/_backup [--compact]
```

备份用 **SQLite 在线备份 API**（一致性副本，不是文件拷贝），并记录 `sha256`。
SQLite 删行后文件不一定立即缩小；`--compact` 才做压缩（`VACUUM`），失败**单独报告**，
不伪报已释放空间。365 日控制**时间范围**，不承诺固定文件大小。
