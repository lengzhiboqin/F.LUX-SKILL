# 最终库字段字典与表关系

**唯一事实源**：一个 SQLite 库（`_data/flux.db`）。**不再保留「中间库 → 精选库」两层。**

## 一、对象总览

```
事实表（每入库表一张，19 张**全部**入库）
├─ 业务列（由 cleaning_rules.json 的 renames / drop_cols 决定）
├─ 来源列  业务日期、数据平台、数据表、采集时间、渠道口径
├─ 派生列  _是否汇总行(INTEGER)、门店标准ID
└─ 库管列  _行序号(INTEGER)、_scope_id(TEXT)、_batch_id(TEXT)

元数据表
├─ _catalog        指标目录：列名 → 单位 / 粒度 / 正式或待核来源 / 规则版本（按 scope 分行）
├─ _store_master   门店主档：非日期型，**不随保留期误删**
├─ _coverage       日期/范围覆盖与状态（含无事件）
├─ _lineage        行级来源定位：原件路径 + SHA-256 + 批次
└─ _batch          成功批次与规则版本（**提交是否发生的权威证据**）
```

## 二、事实表主键与库管列

| 列 | 类型 | 含义 |
|---|---|---|
| `_行序号` | INTEGER NOT NULL | **组内**序号；同一业务键的多行用它区分（一单多商品等真实多明细） |
| `_scope_id` | TEXT NOT NULL | 范围键：`all` 或 `channel:100` / `store:S0001` 等；**不同范围不共用键** |
| `_batch_id` | TEXT NOT NULL | 写入该行的批次 |

**主键** = `业务键列… + _scope_id + _行序号`。
业务键逐表声明（`business_key`），例如：

| 表 | 业务键 |
|---|---|
| 门店经营指标 | 业务日期 + 门店标准ID |
| 评价数据 | 评价提交时间 + 店铺ID + 订单商品 |
| 商品流量_近30天（快照） | *无业务键* —— 整表替换，按窗口结束日判新旧 |

## 三、来源列与派生列

| 列 | 取值/口径 |
|---|---|
| `业务日期` | `YYYY-MM-DD`。牵牛花取**文件名**日期；闪购取**日期列** |
| `数据平台` | `牵牛花` / `闪购` |
| `数据表` | 表名（与注册表一致） |
| `采集时间` | 原件里的批次标记（原 `_采集日期` 的值并入此处） |
| `渠道口径` | 逐表声明，如 `全渠道` / `美团闪购单渠道` |
| `_是否汇总行` | `1` = 汇总行（**不摊到门店**），`0` = 明细 |
| `门店标准ID` | 由门店主档匹配得到；**未匹配留空待核，不猜 ID** |

## 四、`_catalog`（指标目录）

| 列 | 含义 |
|---|---|
| `table_name` / `column_name` / `scope_id` | 主键三元组 |
| `unit` | `元` / `比率` / `百分点` / `null`（按列名规则判定，不靠猜） |
| `grain` | 当前写入 `day` |
| `formal_source` | `原件直取` 或 `null` |
| `status` | `formal` / `pending`（**待核指标查询不出正式值**） |
| `rule_version` | 生成本行时使用的规则版本 |

> 注意：`商品毛利率` 这类名字带「率」但**不是**比率口径误用、`top80%商品缺勤损失`
> 这类带百分号的**标签列**都不按数值处理；金额列由规则**逐表声明**，不靠关键字批量判定。

## 五、`_coverage` / `_lineage` / `_batch`

| 表 | 关键列 | 用途 |
|---|---|---|
| `_coverage` | table_name, business_date, scope_id, window_start, window_end, status, rows, batch_id, rule_version | 判「某表某日某范围」是 `validated` 还是 `no_data`；含无事件也要有记录 |
| `_lineage` | table_name, business_date, scope_id, batch_id, source_path, source_sha256, row_count | 从任意一行**反查原件与校验和**，自检据此独立复算 |
| `_batch` | batch_id(PK), business_today, rule_version, committed_at, inserted, replaced, expired, status | **提交权威证据**；恢复时先查这里有没有已提交记录 |

## 六、表关系（查询路径）

```
用户问「某店某指标」
  → _catalog  取 单位/状态/来源（pending 则不出正式值）
  → 事实表    按 业务日期 + 门店标准ID + _scope_id 定位行
  → _coverage 说明该表该日是否 validated / no_data
  → _lineage  给出原件路径与 SHA-256，供复核
```

- 按**指标、门店、日期、渠道/窗口**定位；返回数值、单位、粒度、覆盖、来源。
- **两平台同口径不能重复相加**；全店汇总行不摊到门店。
- **长编号保真**（纯整数文本不走浮点）；**空值不填 0**；百分比与百分点不混用。

## 七、修订与保留

- **修订 = 整组替换**：「表 + 业务日期集合 + `_scope_id`」整体删后插，避免幽灵行。
- 快照表整表替换，拒绝更旧的窗口结束日。
- 事实按 `业务日期` 保留 **T-365 ~ T-1**（含两端 365 个自然日）；
  快照按**窗口结束日**判期，**不裁切内容**；`_store_master` 等非日期型**不误删**。

### 取数 SQL 模板（可直接改参数执行）

```sql
-- ① 某店某指标某天
SELECT "业务日期", "有效订单金额", "有效订单数"
FROM   "f_门店经营指标"
WHERE  "门店标准ID" = 'S0001' AND "业务日期" = '2026-09-30';

-- ② 某店某指标一段时间（按日）
SELECT "业务日期",
       SUM(CAST(REPLACE("有效订单金额", ',', '') AS REAL)) AS 有效订单金额
FROM   "f_门店经营指标"
WHERE  "门店标准ID" = 'S0001'
  AND  "业务日期" BETWEEN '2026-09-01' AND '2026-09-30'
  AND  "_是否汇总行" = 0          -- 关键：汇总行不摊到门店，单独统计时要排掉
GROUP  BY "业务日期" ORDER BY "业务日期";

-- ③ 查某指标的单位/口径/是否正式（取数前必做）
SELECT column_name, unit, grain, status, formal_source
FROM   _catalog
WHERE  table_name = 'f_门店经营指标' AND column_name LIKE '%金额%';

-- ④ 查某表某日是否真的采到了（避免用空值当结论）
SELECT business_date, status, rows, batch_id
FROM   _coverage
WHERE  table_name = 'f_门店经营指标'
  AND  business_date BETWEEN '2026-09-26' AND '2026-09-30';

-- ⑤ 反查某行的原件与校验和（复核用）
SELECT source_path, source_sha256, row_count
FROM   _lineage
WHERE  table_name = 'f_门店经营指标' AND business_date = '2026-09-30';
```

### 取数四条硬规矩（违反即结论错误）

1. **金额是文本**，带千分位逗号。做数值运算前必须先
   `CAST(REPLACE(列, ',', '') AS REAL)`；长编号（订单号、SKU、店铺ID）**不要**转数值，避免丢精度。
2. **汇总行不能当门店数据**：`_是否汇总行 = 1` 的行是全店合计，
   按门店统计时必须 `WHERE "_是否汇总行" = 0`，否则重复计数。
3. **两平台同口径指标不能相加**：`f_门店经营指标`（牵牛花）与 `f_门店成交明细`（闪购）
   口径不同，不要跨表 SUM。
4. **先查 `_coverage` 再用数**：状态不是 `validated` 的日期说明没采到或没入库，
   不能拿空值当「当天为 0」。

## 八、只读保证

自检（Python）与查询（Node `query.mjs`）都启用只读：
`sqlite3.connect("file:…?mode=ro", uri=True)` / `PRAGMA query_only=ON`
（Node 侧 `new DatabaseSync(path, {readOnly:true})`）。
自检还会对库做**前后指纹比对**，一旦发现只读操作改库即报 `DB_MUTATED_BY_CHECK`。
