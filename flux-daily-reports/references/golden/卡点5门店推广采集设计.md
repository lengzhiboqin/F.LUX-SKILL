# 卡点5 门店推广数据采集与入库设计

> 实测时间：2026-10-13 中午（约12:50–13:00），账号「芙乐」
> 结论：**采集难度低，可在现有技能内快速落地，无需 token。**

## 一、数据怎么取（已实测跑通）

**平台域：** `waimaieapp.meituan.com`（闪购「门店推广」进入）
**鉴权：** 同域 Cookie 即可，**不需要 token**（省略 token 直接成功；错误 token 会触发 logon）
**广告账户：** `acctId=226094983`（品牌级，全店通用，已验证4店）
**门店标识：** `wmPoiId`（美团闪购ID，门店主档 47 店有值）

**三个接口（均 GET，相对路径）：**

| 目标 | 接口 | 关键参数 |
|---|---|---|
| 今日实时（按小时） | `/ad/v3/statistics/shangou_onestop/today/info` | acctId, wmPoiId, platform=0 |
| 近7日（汇总+按天，含昨日） | `/ad/v4/effect/multi/shangou_onestop/history` | days=7 |
| 近30日（汇总+按天） | `/ad/v4/effect/multi/shangou_onestop/history` | days=30 |
| 自定义/历史回采 | 同上 | startDate=YYYYMMDD&endDate=YYYYMMDD |

## 三、字段口径

- **花费**：`debit`（历史）/ `cost`（今日），单位**分**，入库转元
- **曝光**：`showCount.poi`
- **点击**：`clickCount.poi`
- **点击率**：`clickRate.poi`（%）
- **加购/收藏/订单**：`addCount` / `collectCount` / `orderNum`（当前多为0，口径可能归因较严）
- **同行对比**：各指标 `.peer`（附近同行均值，用于对标）
- **推广天数**：`promotionDays`
- 今日 `today[]`：24 小时段数组

## 四、采集难度：低

- 浏览器只需打开广告平台一次（Cookie 守护，登录复用现有机制）
- 纯 JSON 接口，47店 × 3 ≈ 141 次 fetch，预计 **1–3 分钟**
- 无大文件、无异步导出、无 13 分钟等待
- 标准 API 比页面导出更稳定；昨日按天数据在采集时已就绪
- 就绪兜底：若昨日/当日为空，按"数据未就绪"等待重试，不把空当0

## 五、数据交付（入库设计）

**表1：`f_门店推广日效果`（核心，推荐）**
- 粒度：门店 × 业务日期 × 推广产品
- 列：业务日期、门店ID、门店名、推广产品、推广天数、花费、曝光、点击、点击率、加购、收藏、订单、同行曝光、同行点击、同行花费
- 数据量：47 × 365 ≈ **17,155 行/年，不足 10MB**
- 业务键：(业务日期, 门店ID, 推广产品)，按天 INSERT，重复采整组覆盖
- 用途：哪家店在投/没投、花了多少、效果趋势、与同行对标、为自动化判断"是否要开/关/调价"提供依据

**表2：`f_门店推广今日实时`（可选）**
- 粒度：门店 × 小时（盘中实时花费/曝光/点击）
- 数据量：47 × 24 × 365 ≈ 41万行/年（约200MB）；建议只留当日快照
- 用途：白天盘中监控预算消耗

## 六、落地方式

- 在 `flux-daily-reports` 上迭代到 v0.3（与路径B同一版本）
- 新增：推广采集脚本、2 张表、cleaning_rules / metrics / table_registry / schema 同步
- 采集时机：每日采集批次内；历史窗口可经 startDate/endDate 回采
- 扩展：点金推广 / 铂金展位等其他产品若后续启用，按各自 prodTypeName 平行接入
