## 二、四类补齐路径

### 路径A：改采集时机即可（卡点 3、7）—— 成本最低
- **卡点3**：商品流量近30天从早 08:30 剥离，改到 **14:30 后独立晚批次**采集；加窗口/量级/环比三道验收门（见 verify_goods_flow.py）。
- **卡点7**：评价数据随就绪后采集，已正常。
- 见效：明天 14:00 后即可采到正确数据。

### 路径B：平台有数据，新建采集能力（卡点 2）—— 断货闭环核心
- **数据源（已实测）**：牵牛花 → 商品 → 门店商品
  - 路由：`#/unifiedGoods/store/spu-list`
  - 全量：105,340 条（门店×商品），已下架 4,128、不符合渠道规则 14,954、活动中 2,894
  - 字段：门店、商品名、SPU、商品类型、**渠道状态（售卖/停售/售罄/已下架/不符合规则）**、**渠道库存**、零售价、月售
  - 支持「导出」（异步任务）
- 辅助：库存 → 库存查询 / 库存查询-新 / 效期预警
- 做法：按「渠道状态/库存」筛选导出，产出 **商品×门店 的缺勤明细**（商品名/SPU + 状态 + 库存），供断货任务直接点名「补哪几个品」。
- 需新建采集脚本（不在『数据报表』模块，在『商品』模块），并先对齐「缺勤」口径（售罄/停售/库存0/有库存不可卖）。

### 路径C：平台显式 0，需查「功能是否开通」（卡点 1、6、4）
- 卡点 1 / 6：top80、A级属平台「智能商品诊断/补货」类指标，大量门店 = 0 说明平台未给这些店算出商品池。
  - 需在平台页面核对：是该店未开通此功能、未配置商品基线，还是平台未计算。
  - 若需开通/配置 → 属业务侧动作；开通后才会有值。
- 卡点 4：骑手取货时长 = 0 的门店，需确认是否自配送 / 快取 / 不同配送方式导致该口径不记录。
- 注意：这些 0 连续多天稳定存在，**不是采集时机问题，重采补不出来**。

### 路径D：平台没有，先确认业务（卡点 5）
- 牵牛花「营销」仅含促销/活动，**无付费广告/竞价/点金**。
- 闪购后台登录失效，菜单明天登录后确认。
- **需先问业务：F.LUX 有没有在做付费投放？**
  - 没做 → 不存在投放数据，诊断系统不应对该指标提需求。
  - 有做 → 美团即时零售广告入口通常在单独的商家版/推广中心，找到后再建采集。

## 三、执行顺序（按投入产出比）

1. **明天 14:00 后**：验证卡点3（脚本式导出 + 页面导出对比，同时确认闪购营销菜单/卡点5）。
2. **本周**：开发卡点2「门店商品状态」采集脚本（路径B），对齐缺勤口径，并入晚批次。
3. **同步核查**：卡点1/6 在平台是否需开通；卡点4 配送方式口径（路径C）。
4. **业务确认**：卡点5 是否投放（路径D）。
5. 全部新采集都套「一表一契约 + golden + 比对门 + 确认落盘」机制。

## 四、历史缺口说明（不伪造历史）

- 卡点3 商品流量：平台历史窗口本身稀疏，**无法回溯补全历史全量**；只能从修复日起采到正确快照。

- 结论：以「修复后向前正确累积」为主，不伪造历史数据。
